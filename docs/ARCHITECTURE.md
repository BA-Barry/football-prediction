# 系统架构与预测线路

## 目标

项目研究的是赛前概率，而不是赛后解释。每场比赛至少保存主胜、平局、客胜三项概率及生成时间；可选保存比分矩阵、总进球、半全场、让球风险、来源快照和模型版本。赛果在比赛结束后单独接入评分，不能回写已有概率。

## 五条预测线路

`football_model.multiline`定义五条可分别评分的线路：

1. `statistical`：球队、比分或分类模型的完整1X2概率。
2. `llm_independent`：只看有时间戳的事实包，不看统计概率和市场赔率。
3. `market`：同一观察时点的赔率去水概率。
4. `llm_model_informed`：LLM明确看过统计资料或历史模型估计，不能称为独立。
5. `joint_pool`：只在权重来源可说明时生成；组件缺失时不填补概率。

助手综合判断可以解释线路为何分歧，但不自动产生第六组概率。若需要数值融合，必须保存组件、权重、权重学习样本和学习截止时间。

## 主要统计组件

- `DateTeamGoalModel`和`DateTeamXgModel`：按日期截断、时间衰减的球队进攻／防守及主场效应。
- 比分分布：独立泊松、Dixon–Coles低比分修正、双变量泊松及CMP等研究组件。
- 结果分类：多项逻辑回归、树模型、平局分支及条件主客方向研究。
- 状态与信息：近况窗口、跨赛季延续、射正、赛程负荷、人员参与、新闻语义和历史首发研究。
- 评级与融合：KickScore、多路评级、市场融合，以及由更早真实前瞻样本学习的单权重池。

这些组件的存在表示代码和研究已接通，不表示它们全部被当前主线采用。对应实验报告保存在`outputs`，详细接口沿革在`model_v2/INTEGRATION.md`。

## 时间和身份边界

- 历史模型训练规则为`match_date < forecast_cutoff`或`match_date < 被重建的历史比赛日期`。
- 人员新闻的`news_added`是来源元数据，不能自动解释为受伤发生时间。
- 0分钟、缺失记录、跨队记录和未知身份分别保存。
- 当前首发未公布时，不用实际首发或实际分钟生成赛前概率。
- LLM输入包明确声明是否接触统计概率、市场、其他LLM和目标赛果。
- 同一场比赛的多个版本沿用同一fixture ID，不把版本数当作独立比赛样本。

## 目录职责

- `model_v2/src/football_model`：可复用的领域对象、模型、评分和数据适配器。
- `model_v2/tests`：普通单元与集成测试。
- `work`：带日期的实验、采集、核对和报告入口；多数需要本地数据。
- `data`：Git只包含可公开的小型示例，其余由使用者按来源许可准备。
- `outputs`：研究说明及一个完整的历史赛前示例。
