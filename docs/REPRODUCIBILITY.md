# 环境、数据与复现说明

## 项目根目录

代码不依赖盘符、用户名或固定文件夹名称。路径解析顺序是：

1. 命令行显式传入的根目录；
2. 环境变量`FOOTBALL_MODEL_ROOT`；
3. 根据当前源码文件位置自动找到仓库根目录。

通常不需要设置环境变量。只有从仓库外调度旧研究脚本，或把数据目录与源码部署在特殊位置时才设置：

```text
FOOTBALL_MODEL_ROOT=/absolute/path/to/football-prediction
```

所有默认写入目录都位于项目根目录下：`data`、`outputs`、`work/tmp`和各类缓存。使用者可以把整个仓库放在任意有写权限的位置。

## 安装

需要Python 3.12+和Git。跨平台入口：

```bash
python scripts/bootstrap.py
```

脚本在仓库内创建`.venv`并以editable模式安装项目和测试依赖。环境目录也可自定义：

```bash
python scripts/bootstrap.py --venv /path/to/venv --extras test,multi-rating
```

不想使用引导脚本时，可手动创建虚拟环境后运行：

```bash
python -m pip install -e ".[test]"
```

## 可立即复现的范围

- `python -m football_model.demo`：完全合成的阵容情景演示，不需要数据下载。
- `python -m pytest`：代码测试；少数数据适配测试可能需要其夹具或可选依赖。
- `outputs/英超人员协作前瞻_20261029`：可直接阅读的历史概率、来源约束和评分初始状态。
- `data/epl_adjusted_context_20261029`：已保存的条件xG解释、小型模型和参数。

完整研究不能只靠本仓库的15MB内容重跑，因为公开仓库有意不分发约11GB的原始下载和派生数据。缺少数据时脚本应失败并指出路径，不能自动构造替代观测。

## 研究脚本

`work`下的脚本保留研究日期，主要用于审计和重放。运行方式：

```bash
python work/<script_name>.py --help
```

脚本通过同目录`project_paths.py`定位仓库。脚本需要哪些输入，以文件顶部常量、参数帮助及对应输出报告为准。部分历史脚本没有完整命令行封装，属于研究记录，而不是稳定公共API。

## 保存模型

`.joblib`只应从可信仓库加载；反序列化文件可以执行代码。模型是否兼容取决于Python和依赖版本。参数JSON与模型同目录保存，便于不加载二进制时检查训练范围。

## 历史路径

已保存JSON可能含生成机器当时的绝对路径。这些字段是来源／运行证据，不是新的环境配置。新代码只通过项目根目录解析输入。Markdown报告链接已尽量使用相对路径；未上传的大型文件链接自然无法在GitHub打开。

## 可比性要求

比较模型时应固定比赛集合、提前量、输入政策和评分分母。推荐同时报告：

- 多分类LogLoss；
- Brier分数；
- 1X2首选命中率和并列规则；
- 每条线路的可用覆盖；
- 校准情况及置信区间；
- 训练截止、赛果可知时间和预测生成时间。

挑选高置信度比赛可以提高命中率，但必须同时报告覆盖率，不能把双选命中当成单选准确率。
