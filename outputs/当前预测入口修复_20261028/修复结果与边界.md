# 当前预测入口：同日支持与生成时点修复

2026-10-28。上一轮完成8条既存概率机制的同场分解，本轮属于已有预测入口的普通修复；条件主客方向的新训练目标仍在等待用户选择。没有新模型拟合、没有新比赛预测、没有查询或结算新赛果。

## 已复现的具体问题

1. **过期批次先训练后报错。** 原rich入口在检查目标是否已开球前，会拟合两个基础专家和两个树模型。旧单场入口也先拟合再检查10月25日的截止。独立检查将时钟置于11月4日，以仅记录触达的替身运行，两个旧入口都先触达拟合；该探针没有真实训练、写文件或联网。
2. **同日未开球的目标不能进入旧rich入口。** 它一律调用严格要求F<D的接口，而项目已经有F=D的同日接口。错误在四次拟合之后才出现，既浪费执行，也妨碍按真实提前量使用已有模型。
3. **档案观察时间与生成时间没有清楚并列。** rich入口使用10月26日固定快照，本次生成时刻却实时取now；赛程确认的原checked_at没有清楚带到主要报告。数据没有因此变成新观察。源确认实际为2026-10-26T02:55:08.782562Z；Understat英超资料末场为10月25日，官方补充已填补Football-Data较旧记录的缺口，不能误说当前比分仅到10月19日。
4. **只检查启动时刻。** 已启动任务若长时间挂起、直到目标开球后恢复，原rich入口缺少在最终生成时刻复核。因为它原本拒绝同日输入，不能把这描述为普通赛前数十秒运行的必现错误；同日接口接通后也需要保留生成结束时的真实检查。

## 实际改动

- rich入口在资料加载与拟合前核对完整目标批次的身份、数量、既有状态记录和真实开球时间；过期批次直接报明原因，不静默删除已过期场次后缩小批次。
- 同日请求复用已有`for_same_day_match`，隔日请求仍用`for_match`。两者仍严格使用日期<F的历史，没有把当天已经结束的其他比赛顺手加入训练或特征。
- 开球、计算截止和提前量统一按UTC日期解释。报告按实际逐场提前量记录范围，不再固定写“提前5—7天”。
- 报告并列本次计算起始、实际生成完成时间和原赛程状态观察时间；记录档案年龄，明确`live_status_refetched=False`，没有添加任意资料失效时限。
- 在保存概率、LLM事实包、特征报告及运行记录前，按实际生成完成时刻再次核对开球。跨过开球会报错，不能继续标注为有效赛前概率。此前可能已保存模型产物，因此不能声称整次失败完全没有文件写入。
- 旧单场入口把已有截止检查前置，同时保留生成结束后的检查。历史预测和资料快照没有回写。
