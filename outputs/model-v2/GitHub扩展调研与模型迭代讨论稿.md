## 先说明当前状态

本轮对 **21 个不同 GitHub 项目**进行了 README／方法、许可和相关代码的分工核查，范围覆盖统计预测、动态球队实力、球员在场影响、事件数据和采集工具。不是按星数排名，也未独立复现各项目宣称的预测或收益表现。部分统计仓库在 G 盘作浅克隆审阅；没有运行其抓取器或训练脚本。

已形成可运行的 v0.2 模块、复用一个经过审阅的比分分布组件，并完成合成验证。**没有启动真实比赛／真实球员训练，没有形成经过样本外验证的新实战概率，也没有更新旧 Excel 的推荐方向。**

本稿中“建议”是选型判断，不是已经完成的功能。“项目支持某种方法”也不等于“本项目已经接入或验证该方法”。

用户已确认的方向：**双轨对照，验证后再决定赔率融合。** 独立模型概率与市场去水概率分别保存；融合后结果不能覆盖前两者。权重不先拍定。

## 二、已经实际复用了什么

1. 复制 penaltyblog 的 `FootballProbabilityGrid` 所在源文件，保留 MIT 版权许可。只导入网格容器，原文件未改动。
2. 直接使用 scikit-learn 的 `DictVectorizer` 和 `PoissonRegressor`，而不是从零重写优化器。球员模块则用 SciPy 稀疏矩阵与优化器实现实验性正则 log-rate 模型。
3. 没有将所有项目安装进环境。soccerdata 是优先候选采集器；panna 和 footBayes 是设计参考；kloppy／socceraction 等等有事件数据后再评估。

复用时发现一处具体问题：被审阅的 penaltyblog 外部 lambda 网格工厂中，非对称主客进球率的 1–0 与 0–1 修正因子，与该库本身的拟合模型实现不一致。见[网格工厂源码](https://github.com/martineastwood/penaltyblog/blob/master/penaltyblog/models/football_probability_grid.py)、[拟合模型概率源码](https://github.com/martineastwood/penaltyblog/blob/master/penaltyblog/models/probabilities.pyx)。

当前不调用这个工厂，而是独立按标准交叉项构造矩阵，再交给复用容器。已用主客进球率不相等的测试验证边际均值和概率总和；这不是在声称该库的拟合 DC 模型也有同一错误。没有向 GitHub 发 issue／PR。

## 三、概率从哪里来，怎样变化

建议的完整链条是：

`预测时点已知的历史 → 球队条件进球率 → 阵容／换人情景 → 各情景比分分布 → 概率加权 → 胜平负与总进球等玩法`

另一路：`同一预测时点的市场报价 → 去水概率 → 与独立模型对照 → 验证后才决定融合`。

### 球队层

当前可训练原型形式为：

`log(lambda_H) = 总体项 + 赛事项 + 本队进攻 - 客队防守 + 主场项`

客队类似，不加主场项；中立场单独标识。近期赛果权重随时间衰减，但衰减速度、正则强度不能当成已学得结论。默认参数只为了让接口可运行，真实训练必须在更早验证期选择。

后续可以比较动态强度、xG 目标与实际进球、休息天数和赛程项；每加一类特征，都要观察未来时段的概率评分与校准是否改善。并非特征越多越准确。

### 球员层：不是“明星缺席固定扣 5%”

对球员 p，研究攻防两个系数；同时控制队友、对手、在场时长与情境，减少把弱对手、红牌或领先后收缩误认成个人能力的风险。正则化使小样本系数收缩；但依旧是条件关联，不是因果能力证明。

对一段固定阵容时段 s：

`lambda_H,s = 条件参考进球率_H × exp(本方进攻变化_s - 对方防守变化_s)`

各时段按持续时间积分。替补必须明确替代谁，并共同构成合法的 11 人阵容；不是把所有伤停影响线性累加。正式比赛的预计 990 球员分钟包含替补，门将合计 90 分钟。赛后实际换人只可作训练标签，不能放进当场赛前输入。

如果只有预计分钟，当前仍提供平均分钟近似，但显式标注。两种计算并不总等价：基础率为 1，一个球员在场时强度乘 4、其余时段乘 1，各占半场，分时段积分是 2.5，而先平均 log 效应再指数化只有 2。这个大效应仅用于揭示数学差异，不是现实球员评级。

若首发未确认，使用几套相互一致的完整阵容／换人路径，各自算比分分布，再按概率合并。不能先平均所有 lambda 后当成同一 Poisson 分布，也不能把相关球员独立抽取而拼出不可能阵容。

### 还存在的关键衔接问题

球队历史平均率是边际量，不必等于“平均分钟阵容”的条件率。即使分钟参考窗口一致，指数非线性仍可导致整体均值上漂。因此，当前球队输出明确是 `team_marginal`，不能直接传入要求 `conditional_reference` 的阵容修正器。真实训练需要联合估计，或按训练期阵容分布校准条件基准，不能只改字段名称。

这是下一阶段必须实测的统计问题，不是加一个人为伤停系数就能解决。参考比赛 ID／权重与阵容数据的实际关联仍待适配器完成。

门将也要谨慎：防守 xG 允许量主要描述限制机会，不足以单独识别扑救能力；需另外研究进球、射门后 xG、射门质量和样本收缩。缺少证据时不把门将名气换成确定百分比。

### 市场层：按用户已选的双轨路线

最简单的去水为 `q_i = (1 / odds_i) / sum(1 / odds)`；这是比例去水假设，不是唯一真值。后续可以比较其他去水方法及多公司报价一致性，不能由低赔率推断高价值。

若历史验证支持融合，原型能对比分网格的主胜／平局／客胜三个区域重加权，使最终 1X2 符合混合目标，而其他全场玩法仍从同一矩阵导出。它保留原条件比分形状；**仅匹配 1X2 不会自动校准总进球或大胜尾部**，仍需分别评分，必要时利用独立大小球盘口证据。

独立摘要、市场摘要、融合摘要分别输出；情景范围明确注明是融合前范围。市场可能已经消化伤停信息，所以不能假定“市场修正 + 同一伤停再修正”自动创造额外优势。当前尚未学到任何融合权重。

## 四、能否用于五大联赛和欧冠

框架可以，参数和数据覆盖不能直接照搬。

- 五大联赛样本相对多，可共享方法并估计各联赛／赛季差异；同样要处理升班马、转会和教练变化。
- 欧冠、欧联、欧协联需要跨联赛强度桥梁、欧战对手连接、客场旅行、赛程与轮换证据；只有各国内赛果且对手网络不连通，球队都见过也不代表能比较其绝对强度。
- 主客、中立场、90 分钟／加时、淘汰赛首回合／次回合不能混用；不能仅把 competition 字段改成“欧冠”就宣称适用。
- 对新球队／少出场球员需要明确先验与覆盖说明，不默认为同级平均且给高置信度。

建议先用覆盖可靠的五大联赛验证基础行为，同时保留欧战作为单独赛事切片评价。是否同一联合模型、分层模型或分开拟合，应由数据连通性和时间外推结果决定，而非先拍定。

## 五、公开数据的现实缺口

1. [soccerdata 的缺阵读取代码](https://github.com/probberechts/soccerdata/blob/master/soccerdata/whoscored.py)提供球员、原因和状态等，但没有证明历史赛前某时刻已获知该消息的发布时间字段。今天读取历史页面不等于拥有历史消息快照。
2. [Transfermarkt 阵容表](https://github.com/dcaribou/transfermarkt-datasets/blob/master/dbt/models/curated/game_lineups.sql)有比赛日期和首发／替补，但不包含首发公布时间；且当前公开集停更。不能用于重建本轮实时伤停。
3. [Football-Data 字段说明](https://football-data.co.uk/notes.txt)区分 pre-closing 与 closing；不带 C 的列不能一律叫“开盘”，更不能当成完整逐时赔率。赛前 24 小时模型需要当时可获得报价。
4. [StatsBomb 公开赛事清单](https://github.com/hudl/open-data/blob/master/data/competitions.json)出现欧冠不等于整季覆盖。例如 [2018/19 欧冠比赛文件](https://github.com/hudl/open-data/blob/master/data/matches/16/4.json)只有决赛，不能拿来训练完整欧冠赛季。
5. [football-data.org 覆盖](https://www.football-data.org/coverage)与[价格说明](https://www.football-data.org/pricing)将免费赛果覆盖、认证访问和更深的阵容／换人服务分开；未开通账号或购买服务。

本轮没有建立一个可核实的、免费且完整覆盖“五大联赛＋欧冠”的历史赛前伤停发布时间数据库。不能将未知填成“无人缺阵”。下一步应先实测可用来源，再决定特征和训练范围。

## 六、训练和评价安排（尚未启动）

1. 和用户确定预测时点、首轮赛事范围及数据成本边界。
2. 在 G 盘接入少量合法可用样本，核对覆盖、ID、时区、结果时间、已知首发和赔率来源。
3. 先验证球队模块，然后处理球队边际率与球员条件率的衔接；数据不足的部分明确留缺，不制造完整记录。
4. 用较早训练期、随后验证期选择正则、时间衰减和融合方法；最后测试期不再用于选择这些设置。不能随机打乱比赛当成真实赛前检验。
5. 分别看 Log loss、Brier、RPS、校准曲线和各联赛／预测时点切片。命中率不能替代概率校准。
6. 再比较加入球员信息前后的增量表现，以及伤停、替补门将、轮换等小样本情境。参数区间与阵容情景范围分开；按比赛／赛季相关结构估计不确定性。
7. 只有这些结果出来后，再讨论价格优势与串关。收益还受可成交赔率、相关性、限额和成本影响，不能只看回测 ROI。

## 七、已做的实际验证

2026-10-22：**33 项合成测试通过**；合成演示成功生成。验证涵盖非对称 DC 修正、分布总和与边际均值、竞彩／亚洲让两球差异、替补方向、门将替换方向、时段积分、情景混合、未来信息拒绝、预测身份关联、双轨保留、无效标签拒绝及延迟赛果切分。

这证明上述程序在受测情境的行为，不证明足球预测准确率。演示参数及情景权重全为人为构造，不是经验拟合。

针对最初勒沃库森问题，结算实现保持：**竞彩让两球让胜必须净胜至少 3 球；净胜恰好 2 球是让平，不是让胜走盘。** 亚洲 -2 的净胜 2 球通常走盘，不能用亚洲盘公平赔率套在竞彩让胜上。各赛事具体规则仍需与实际票面核对。

无走盘的公平十进制赔率为 `1 / p_win`；有走盘为 `(1 - p_push) / p_win`。它们是未加模型误差缓冲的零期望门槛，不是推荐买入价。没有真实训练及实时数据支持前，本稿不输出新二串／三串建议或胜率承诺。

## 八、下一次优先和你讨论的选择

**预测发生在什么时候？**

建议保留两版：赛前约 24 小时的预计阵容版，以及官方首发公布后的更新版。前者更早但阵容不确定，后者阵容更明确但赔率也可能已变化。二者必须分别使用当时可知的数据、分别评估，不能把确认首发倒灌进 24 小时模型。
