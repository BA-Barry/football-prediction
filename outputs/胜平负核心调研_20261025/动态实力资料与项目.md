# 动态球队实力与三类概率：源码核对及取舍

核对日期为2026-10-25。本文只作研究建议，尚未安装或训练任何新模型。没有读取当前比赛赛果、首发或新比赛统计。来源包括作者论文、官方仓库及当前源码；版本和接口不能与旧教程混用。

## 首选参考：KickScore，不把“recursive”误当只向前更新

[KDD 2019原论文](https://arxiv.org/abs/1903.07746)用连续时间高斯过程表示随时间变化的实力，做近似后验推断。[作者项目](https://github.com/lucasmaystre/kickscore)采用MIT许可；[当前元数据](https://github.com/lucasmaystre/kickscore/blob/master/pyproject.toml)标示0.2.0、Python至少3.10及numpy/scipy/numba依赖。本轮只静态阅读，没有安装。

可借用的具体位置：

| 源码 | 可以借什么 | 需要适配什么 |
|---|---|---|
| [model.py](https://github.com/lucasmaystre/kickscore/blob/master/kickscore/model.py)中的TernaryModel | 原生胜／平／负似然、observe及probabilities接口 | 逐发布日期的历史前缀、主客映射、失败记录；其默认margin不是本项目已学参数 |
| [kernel/exponential.py](https://github.com/lucasmaystre/kickscore/blob/master/kickscore/kernel/exponential.py) | OU均值回归、时间间隔对应的状态噪声 | 用日数作统一单位，状态在比赛间持续，不按28天归零 |
| [observation/ordinal.py](https://github.com/lucasmaystre/kickscore/blob/master/kickscore/observation/ordinal.py) | 对实力方差积分后的有序probit胜／平概率 | 平局矩匹配源码有数值稳定性待办，极端尾部需要测量，不能事后裁概率遮掩 |
| [fitter/recursive.py](https://github.com/lucasmaystre/kickscore/blob/master/kickscore/fitter/recursive.py) | 状态空间计算 | 同时执行前向Kalman与后向RTS；整季fit后读过去状态会混入未来，必须只拟合已知历史前缀 |
| [observation/observation.py](https://github.com/lucasmaystre/kickscore/blob/master/kickscore/observation/observation.py)中的f_params | 从各item取得预测均值和方差 | 预测方差为分项方差加权和，未表示所有跨队协方差；不是精确联合贝叶斯后验 |
| [作者足球复现](https://github.com/lucasmaystre/kickscore-kdd19/blob/master/lib/kseval/models/football.py) | Constant＋Exponential团队核、主场item、结果方向 | 国家队结果不证明本项目俱乐部或欧战增益；必须重新验证 |

已知历史前缀内允许重估历史状态；问题在于是否吸收预测发布以后才知道的结果，而非“任何平滑都禁止”。未来回看曲线与当时实际发布的预测必须分开保存。

令比赛前实力差近似为N(μ,v)，比赛本身噪声方差固定为1，平局区间为±m，则：

- P(主胜)=Φ((μ−m)/√(1+v))；
- P(客胜)=Φ((−μ−m)/√(1+v))；
- P(平)=1−P(主胜)−P(客胜)。

这里的v只是在该近似模型下的状态不确定性；不包括完整超参数误差、供应商修订或遗漏变量。连续时间外推会改变均值和方差，不能用“上场之后间隔长，所以手动降低胜率”替代它。

**重要反例：不确定性不保证平局上升或三类走向各1/3。** 固定μ=0、m=.35，v从0增至1，平局由约27.37%降至19.55%；固定μ=1.5时，平局随v从0到1再到4约为9.29%→11.26%→9.95%，并非单调。这个[公式示例](G:/Codex/football-prediction-2026-10-22/outputs/胜平负核心调研_20261025/状态不确定性公式示例.json)没有拟合比赛，不能当预测成绩。它说明“有不确定性”并不自动解决本项目平局辨别弱的问题。

## 其他动态项目：保留可复用机制，避免整包替换

| 项目 | 可借内容 | 为什么不排在第一条实施 |
|---|---|---|
| [Whole-History Rating](https://github.com/pfmonville/whole_history_rating) | Davidson三概率、时间变化和不确定性积分 | 全历史会修订过去；必须历史前缀回放。[当前源码](https://github.com/pfmonville/whole_history_rating/blob/master/whr/whole_history_rating.py)的三概率接口没有预测日期参数，不能未经适配就声称传播了停赛至下一场的过程噪声。README分数不作为本项目证据。 |
| [TrueSkill Through Time](https://github.com/glandfried/TrueSkillThroughTime.py) | 技能均值／方差、跨时间传递和平局观察 | 全历史convergence含平滑，发行包和开发分支接口不同；需自己定义完整未来三概率及日历噪声，不是即插即用的足球预测器。 |
| [TrueSkill](https://github.com/sublee/trueskill) | 对局后更新技能与不确定性、平局边界机制 | 评级quality或一个预期得分不是完整1X2；时间推进、主场、球季和概率输出仍需适配。 |
| [OpenSkill](https://github.com/vivekjoshy/openskill.py) | 多队评级和方差更新、概率接口参考 | 通用多玩家任务不证明足球常规时间三分类有效；需核对平局与概率归一的联合定义，不能单取胜率再随意补平局。 |
| [PyBATS](https://github.com/lavinei/pybats) | 动态广义线性模型、状态均值／协方差、先预测后更新 | 原生是一般时间序列框架；足球异步赛程与多球队状态需工程适配，不直接输出可验证的主胜／平／客胜。Apache-2.0。 |
| [footBayes](https://github.com/LeoEgidi/footBayes) | 足球动态Stan模型、Davidson似然、后验样本 | [dynamic_btd.stan](https://github.com/LeoEgidi/footBayes/blob/master/src/stan/dynamic_btd.stan)的已观测时期参数和y_rep不等于未来赛程预测。需正确推进未来状态、逐样本算概率；不为本轮另装R/Stan。 |

这些项目的“处理方差”“有时间字段”“支持draw”是不同能力；均不能据库存在就认定预测优于本项目。暂不把全部库装到现有环境，避免依赖迁移挤掉实际检验。

## 与本项目旧负结果的区别

既有跨季q研究是年度创新的点估计，较早选择q=0；快照残差每28天归零，也没有完整状态方差传播。拟议研究跨比赛持续承接长期与短期状态，直接以三类结果学习，并对状态方差积分。它不是旧q搜索重启、每周刷新或分类树换库。

但是，新线与现有进球/xG线在目标、输入表示及更新节奏上都有差别。它即使更好，也不能把全部差值单独归因于“不确定性”；须设同一三类似然的静态对照。去掉预测方差的版本只作机制诊断，不在后季据分数改选成新赢家。

**建议：只提出一条Constant＋OU、有序probit三分类的有限研究，先测速度与数值，再跑历史前推。** 超参数只在更早数据作有预算的连续估计，不扫核函数、窗口或联赛网格。完整设计见本目录后续实施草案；本轮没有执行这项训练。
