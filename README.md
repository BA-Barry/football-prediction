# 足球赛前概率研究：统计模型、市场与 LLM 协作

这是一个面向个人研究的足球赛前预测项目。它不只输出“看好哪一队”，而是保存每场比赛完整的主胜、平局、客胜概率，进一步给出比分与总进球分布，并把统计模型、市场去水概率、独立 LLM 判断和模型辅助 LLM 判断分开记录。

项目强调三件事：概率必须可追溯，训练与预测必须遵守时间边界，不同路线应先保留各自证据再讨论联合，而不是把低赔率直接解释成高价值或把多个结论机械平均。

## 当前状态

- 核心 Python 包、测试、研究脚本和一个完整的历史预测示例已经公开。
- 所有运行路径均相对仓库解析，不依赖特定盘符、Windows 用户名或固定文件夹名称。
- 合成演示不需要外部数据，可用于检查概率流程与安装是否正常。
- 完整历史研究仍需要约 11 GB 的原始数据和派生材料；这些材料受来源条款、体积和个人研究用途限制，没有随仓库分发。
- 仓库是研究代码和证据档案，不是承诺固定准确率的投注系统。

## 快速开始

需要 Python 3.12 或更高版本。仓库可以克隆到 Windows、macOS 或 Linux 上任何有写权限的位置。

```bash
git clone https://github.com/BA-Barry/football-prediction.git
cd football-prediction
python scripts/bootstrap.py
```

引导脚本会在仓库内创建 `.venv`，并安装项目与测试依赖。随后运行：

```bash
# Windows PowerShell
.\.venv\Scripts\python.exe -m football_model.demo
.\.venv\Scripts\python.exe -m pytest

# macOS / Linux
./.venv/bin/python -m football_model.demo
./.venv/bin/python -m pytest
```

也可手动安装：

```bash
python -m venv .venv
python -m pip install -e ".[test]"
football-model-demo
```

只有从仓库外调度脚本或采用特殊目录布局时，才需要设置根目录：

```bash
FOOTBALL_MODEL_ROOT=/absolute/path/to/football-prediction
```

路径解析优先级为显式参数、`FOOTBALL_MODEL_ROOT`、源码所在仓库。通常不需要设置该变量。

## 模型回答什么问题

对一场比赛，系统的基础输出不是一个标签，而是一组互相一致的概率：

- `P(主胜)`、`P(平局)`、`P(客胜)`，三者之和为 1；
- 主客队预期进球与联合比分矩阵；
- 常见比分、总进球区间和让球相关风险；
- 不同输入情景下的概率变化；
- 统计、市场、LLM 与联合路线的来源、时间和可用性。

一个方向概率最高，只表示在当前信息与模型假设下相对更可能，不代表赔率具有正期望，也不代表适合串关。价值判断还需要把模型概率与去水后的市场概率及可成交赔率比较。

## 方法框架

### 1. 球队进球强度

基础线从赛前可知的历史比赛估计球队进攻、防守与主场效应。研究组件包括时间衰减、对手强度、跨赛季延续、升降级与跨赛事信息。真实进球是主预测目标，xG、射正及其他过程指标作为独立信息或校正线，避免把不同含义的指标直接混成一个分数。

### 2. 比分分布

主客预期进球进入泊松或带低比分相关修正的联合比分模型，由比分矩阵推导 1X2、总进球和具体比分概率。仓库还保留 CMP、平局分支及主客进球分配等研究，但“实现过”不等于“已证明在所有联赛稳定提准”。

### 3. 人员与可用性

球员研究使用较早比赛中的在场时间、位置和进攻／防守贡献，研究分层收缩、未知球员先验以及阵容情景。由于真实首发通常临场公布，正式赛前路线不能假装提前知道首发；合成演示展示的是情景加权机制，不是现实阵容预测。

### 4. 市场路线

赔率先去除庄家水位，得到市场隐含概率。市场概率单独保留，可作为校准参照或经历史前推学习后的融合输入。低赔率仅说明市场认为事件更可能，不自动等于有价值。

### 5. LLM 路线

LLM 用于处理结构化数据难以完整表达的赛前信息，例如赛事重视程度、教练变化、轮换倾向、伤停语义、赛程压力和战术适配。项目区分：

- 独立 LLM：在不看到模型结论时形成判断；
- 模型辅助 LLM：读取统计证据后解释冲突和不确定性；
- 助手综合：在两条路线输出之后形成带理由的收束意见。

LLM 不是自动补齐缺失事实的工具。没有来源或观察时间的信息应标记未知，也不能把赛后信息倒填成赛前依据。

### 6. 联合预测

联合不等于简单平均。仓库研究了固定权重、随时间前推学习的权重和线路可用性处理。一个可靠的联合器至少要知道各路线的预测生成时间、训练窗口、覆盖范围和相关性；权重只可由更早样本学习，再固定到后续比赛检验。

详细数据流和组件边界见[架构说明](docs/ARCHITECTURE.md)，字段含义见[输出格式](docs/OUTPUT_FORMAT.md)。

## 如何避免把训练集当测试集

项目采用时间前推原则，而不是随机拆分后声称具有真实赛前能力：

1. 每个预测样本只允许使用该场开赛前可知的信息；
2. 训练窗口、参数选择窗口和最终评估窗口按时间分离；
3. 每周滚动重训时，目标比赛本身及更晚比赛不得进入特征或参数选择；
4. 预测生成时间与赛果结算分开保存；
5. 比较路线时固定比赛集合、提前量、缺失值政策和评分分母。

推荐同时报告多分类 LogLoss、Brier 分数、1X2 单选命中率、校准和覆盖率。只挑高置信度比赛可以提高命中率，但必须同步报告覆盖率；胜／平双选也不能记作单选准确率。

## 仓库结构

| 路径 | 用途 |
|---|---|
| [`model_v2/src/football_model`](model_v2/src/football_model) | 可安装的核心概率、记录、校准和研究组件 |
| [`model_v2/tests`](model_v2/tests) | 概率、时间边界、来源对齐、缺失信息与评分测试 |
| [`work`](work) | 按研究日期保存的数据获取、训练、审计和报告脚本 |
| [`outputs`](outputs) | 已筛选上传的历史研究报告和预测运行记录 |

| [`scripts/bootstrap.py`](scripts/bootstrap.py) | 跨平台环境初始化入口 |

`work` 中的日期脚本用于审计研究过程，不全是稳定公共 API。它们已使用通用项目根目录，但仍可能要求未上传的原始数据。缺失输入时应明确失败，不能自动制造替代观测。

## 数据、模型与许可边界

公开仓库约 15 MB，原研究目录约 11 GB。未上传内容主要包括 Football-Data、Understat、StatsBomb、Wyscout、FPL 等原始下载，大型特征矩阵、缓存和重复模型。详见[数据与模型范围](DATA_AND_ARTIFACTS.md)与[复现说明](docs/REPRODUCIBILITY.md)。

`.joblib` 文件只应从可信来源加载；反序列化可能执行代码，且兼容性取决于 Python 与依赖版本。数据访问条款和软件许可分别适用，个人研究用途不自动授予原始数据再分发权。

仓库目前没有顶层开源许可证。公开可见不等于自动允许复制、修改或再分发；第三方组件继续遵循各自许可证，见[第三方说明](model_v2/THIRD_PARTY.md)。若项目所有者希望他人正式复用，应另行选择并添加 MIT、Apache-2.0 或其他合适许可证。

## 已知限制

- 不保证覆盖所有联赛、杯赛和跨级比赛；不同赛事的数据质量和动机不确定性不同。
- 伤停、教练意图和赛事重视程度常缺少稳定历史标签，LLM 判断也可能出错。
- 早期研究档案无法完整重建所有网页的首次发布时间与后续修订时间。
- 预测概率的校准会随联赛、赛季和市场环境漂移，需要持续前推评估。
- 当前没有证据支持“普遍达到 70% 单选命中率”；任何此类数字必须同时说明比赛筛选、样本量和覆盖率。
